# Diagnostic protocol AM-0 / 1

This protocol is committed before development or evaluation runs. It is a **bounded diagnostic**, not the full confirmatory study proposed in Nature Compute Lab. The analytical novelty gate already fails; running the diagnostic checks mechanism behavior and correctness. Do not tune after the held-out results, and preserve all measurements.

## Questions

1. Do the reaction-state and coefficient-state implementations agree to floating-point tolerance across complete learning histories, including assembly insertion/eviction?
2. Are all component amounts nonnegative and conserved? Does the learner retain state when labels are withheld?
3. Can the learner improve prediction on previously unseen sequences generated by benign abstract response dynamics?
4. Does the finite pool or adaptive membership help relative to simpler controls under declared resource ceilings?

A positive answer to 3 or 4 does not overturn the mathematical audit.

## Data and independence

Three simulator families, each with independently sampled coefficients. None is a model of a particular organism.

- **Adaptive response:** an input-induced adaptation state attenuates later stimulus response, with a smooth output relaxation.
- **Resource response:** stimulation consumes a replenishing shared resource, creating exposure-history dependence.
- **Delayed feedback:** response depends nonlinearly on a delayed output and the present stimulus, with a separate lag buffer.

The explicit equations are versioned in `assembly_memory/data.py`. All states start at declared values. Input signals are bounded piecewise-constant pulses. The two inputs and previous measured output are available; simulator states/coefficients are not. The same fixed fast/slow history encoder is used by all main methods. It is not guaranteed to be sufficient for exact hidden-state recovery; no impossible exact-identification claim is made.

For each system: 32 training sequences, 12 validation sequences, 20 evaluation sequences, 48 predictions each. The first 4 steps of each are warmup and excluded from fitting/scoring, giving 1,408 unique training labels. Data are generated by split-specific random streams. Evaluation includes new sequences on [0,1]^2. Training omits simultaneous high-high stimulus segments (both inputs > 0.65), while evaluation does not; report both all steps and steps currently in that excluded region. This is limited input-combination transfer, not arbitrary biological generalization.

Development uses two independent systems per adaptive/resource family (seeds 71, 89). Select one learning rate per model from {0.01, 0.03, 0.1} by mean validation nMSE across these four systems, using one pass. No system-specific tuning. Each model gets three configurations. Fixed zero and shuffled-label controls inherit the assembly rate. The held-out run uses five systems per family (seeds 307, 401, 509, 601, 701); the delayed family has no development systems. Development and evaluation arrays/hashes are saved with the output. The output response itself is not altered by observation noise in this first diagnostic.

## Models

- `assembly`: AM-0, at most 20 active features, initial singletons.
- `assembly_fixed`: same update and pools, a fixed deterministic 20-feature catalogue subset.
- `assembly_no_pool`: same support selection/dissolution; g = 1 and alpha = 1, with pool constraints removed. This is an update ablation, not a physically conservative learner.
- `adaptive_lms`: same feature grammar, scores and slot rules, normalized LMS coefficients; same 20 active-feature ceiling. Birth decisions can differ because the residual differs.
- `quadratic_lms`: normalized LMS on all 36 polynomial features.
- `history_lms`: normalized LMS on the eight fixed history coordinates.
- `current_lms`: normalized LMS on constant plus current inputs. A lower-information control; excluded from claims of identical input information.
- `assembly_shuffled`: same input histories, training target labels permuted within the full training set; validation/evaluation targets stay correct. History still contains past true observations, which is available to every model. This tests the outcome association, not removal of all temporal information.
- `assembly_untrained`: no learning, zero output.

An independently written signed-coefficient version is a **correctness witness**, not an independent predictive baseline. We do not count identical numbers twice. No external paper implementation is reproduced. Chemical, learned-recurrent, learned-routing model-bank and multiscale-synapse controls from the broader proposal are deferred because the novelty gate failed. Conclusions are restricted to the listed controls.

## Resource comparisons

Two settings, reported separately:

1. **One pass:** exactly the same ordered 1,408 unique training examples and one label update per example; no replay. Runtime is measured, not matched. Curve metrics are pre-update errors, reported by quarters of the stream.
2. **Common time ceiling:** maximum 0.75 seconds for the same finite training dataset, allowing cyclic replay of its existing examples. Check the deadline before every update; report completed updates, distinct examples seen, and measured overrun. Precompute only the shared history encoding, charged equally as shared preprocessing. Model construction, feature expansion and updates are in the timed interval. Include only systems for which all compared trained models see the full dataset at least once in an equal-data comparison; report exclusions rather than silently changing the ceiling. Inference is separately measured. The timer is a ceiling, not a perfectly identical CPU-operation count. Scheduling/BLAS effects limit exact reproducibility of update counts.

All models have a common **32 KiB persistent-state ceiling**, including learned/static numeric arrays, masks, model configuration and the four history-trace scalars. Report actual state sizes rather than allocating meaningless padding. This is a common-cap comparison, **not exact equality of memory use**. Also report peak Python-traced workspace during a representative audit, and process environment; the dataset and interpreter are not model capacity. A lower-memory control is allowed to use fewer bytes. This pilot does not establish a fully matched Pareto frontier or any advantage against an optimized implementation.

## Metrics and decisions

Primary: evaluation mean squared error / max(training response variance, 0.01). Report per family and paired relative error differences across independent systems. Also report the withheld-combination subset and first/last training-quarter errors. Keep sequence-level errors so systems, not timesteps, are the replication unit. Five systems per family are exploratory: give paired wins/ties/losses and ranges; do not market a significance threshold or 95% accuracy target.

Mechanistic support would require at least a 10% median relative error improvement versus `adaptive_lms` and `quadratic_lms` on **each** family in both settings, without excluding incomplete-data cases, and a measurable contribution of assembly formation or pooling. This deliberately stringent diagnostic gate is fixed before outcomes. Even meeting it would only justify another study of the variant. Failure means no scaling investment in AM-0. Do not choose the next mechanism by retuning on these held-out systems.

Artifact requirements: code revision, source hashes, config, environment, all model predictions, targets, data hashes, development results, selected rates, counters, time and memory. Report any deviations or corrections to the protocol. Use actual timestamps; no fabricated project history.
